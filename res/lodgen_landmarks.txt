# lodgen_landmarks.txt -- the NAMED LANDMARKS of the native .lodi identity join (lane IDENT2, 2026-09-29).
#
# bungo 2026-09-29 (HANDOFF, rulings during MERGE1, item 1): "Landmark rule" -- the pieces of a named
# landmark are ONE group, whatever its size; the rest of the map keeps the contact join (32 u, cap 4,096 u).
# Built into NifSkope (res/nifskope.qrc, :/lodgen/landmarks.txt); `lodgen ... --landmarks <file>` reads
# another list instead, `--landmarks none` reads none. Only the contact join reads it
# (`--identity-join proximity` and `legacy` never do).
#
# One landmark a line, three fields split by '|':
#   name | prefix[;prefix...] | [centreX centreY radius]
# * prefix: the start of the placement's LOD MODEL PATH, compared in lower case with '/' for '\' and a
#   leading "meshes/" and then "lod/" taken off both sides. A placement matches when its path starts with
#   ANY of the prefixes.
# * centre / radius (world units, optional): a matching placement also has to stand within `radius` of
#   (centreX, centreY) on X/Y. Use it when the kit is shared with other buildings (the Hub towers' hightech
#   kit is used all over Boston).
# The rule lines alone make the list's digest (a comment edit moves no bake). Model paths only: no game data.
