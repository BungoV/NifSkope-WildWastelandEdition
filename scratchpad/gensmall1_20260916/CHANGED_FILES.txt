THE HONEST GAP
--------------

Three rows above say NONE in the source column: `src/lodifile.cpp`,
`tests/spells/lodgen_native_decode.py` and `tests/spells/lodgen_native_fields.py`.
Their BEFORE byte counts were never captured and CANNOT now be reconstructed.

Why not, precisely, so the next lane can avoid it rather than just be warned:

  * all three are UNTRACKED in git -- they are earlier uncommitted lanes' work
    sitting in the tree -- so `git show HEAD:<path>` has nothing to return and
    the trick that produced the exact BEFORE for `ba2file.cpp` does not apply;
  * each received at least one REPLACEMENT edit, not only additions, so the
    reverse-arithmetic that recovered `src/nativeemit.cpp` (57,196 + 2,008 =
    59,204, which matched a figure recorded independently) has no fixed point
    to work from here: subtracting what was added does not give back what was
    removed.

The brief asked for before AND after per path. Two of the fourteen paths cannot
be given one, and this is stated rather than filled in with a plausible number.
It is written up as a mistake in MISTAKES_ENTRIES.md with the rule that
prevents it: measure a file the moment you decide to edit it, before the first
edit, and put the three numbers in the report immediately -- not at the end,
when the only copy of the old bytes is gone.

What IS known about all three: CR is 0 now, they are LF-only now, and nothing
this lane did could have introduced a CR, because every edit went in through
Python in binary mode or through the Edit tool on an LF-only file. The
uncertainty is the SIZE of the before, not its line endings.
