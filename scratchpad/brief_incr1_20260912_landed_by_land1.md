1. **The dependency map first** (report section 1, before code): for every output kind, what OTHER chunks/tiles/levels its bytes depend on: terrain skirts and stitched borders, the pyramid's borders and coarser levels, horizon AO (the ray length in units -> chunks of reach), water bodies spanning chunks, the merge pass, the far-ring simplification, texture-array layer assignment, card sets, the native library (append-only?) and the `.lodi` chunk table, manifests, identity indices. Each with the contract line that states it. This map IS the widening rule.
2. **The ledger** `<out>/Terrain/<WS>.lodb` (or the name bungo rules; propose): per chunk at each ring, a u64 hash over the RESOLVED inputs the chunk sees (winning LAND records' VHGT/VNML/VCLR/BTXT/ATXT/VTXT bytes, the placed REFR records in the chunk after load-order override and disable flags, their base records' MODL/MNAM/flags, the LTEX->TXST chain, the model files' and textures' sizes+mtimes or content hashes -- state which and why), plus the generator version and the switch set that produced the bake (a different switch set = full bake). Written by every full bake; read by `--incremental`.
3. **The diff**: on `--incremental <out-dir>`, resolve the load order as a full bake would, hash every chunk, compare to the ledger, mark dirty; widen by the dependency map (item 1); print the census (dirty / widened / copied / rebaked per ring and level, and WHY each widened chunk was widened, by rule name); rebake the set through the SAME deterministic queue BAKEPERF1 built; copy everything else through unchanged; rewrite containers in place (the `.lodl` blocks, the pyramid tiles and their coarser levels, the `.lodi` chunk table, appended library rows, appended array layers) and re-sign every CRC and corpus hash the contracts define.
4. **Refusal = full bake**: any case the ledger cannot answer (missing ledger, generator version changed, switch set changed, a dependency the map does not cover) refuses incremental BY NAME and runs the full bake -- the fallback arm, named in the census.
5. **THE GATE**: on both regions, (a) full bake -> ledger; (b) a synthetic one-cell edit applied through a test plugin (an override of one LAND record's VHGT + one moved REFR; write the plugin with the tree's own ESM tools or a byte patch of a copy, never his installed files); (c) full bake of the edited world; (d) incremental bake of the edited world from (a); (e) `cmp` EVERY file of (c) vs (d): byte-identical or the lane fails. Then the same with: a plugin removed; a texture replacer (one DDS mtime/content changed); a new model added. The census for the one-cell edit prints the dirty count (predict it from the dependency map BEFORE running: e.g. 4 chunks + N neighbours + M tiles; the prediction and the measurement both in the report). Floor: a deliberately wrong widening (AO reach halved) shown to break identity.
6. **Time**: the four stage times for the full bake vs the incremental bake on the 25-chunk region, printed.
